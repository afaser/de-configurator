# de-configurator 🚀

**de-configurator** — это легковесный и невероятно быстрый фоновый демон на Rust, который берет на себя управление всей конфигурацией твоего Linux-окружения (тайлинговых оконных менеджеров вроде `bspwm` или `hyprland`).

Если тебе надоело держать десятки разрозненных скриптов автозапуска, настраивать горячие клавиши в одном месте (`sxhkd`), правила для окон в другом, а переключение VPN в третьем — этот проект создан для тебя. Он объединяет всё это в единую реактивную систему, управляемую одним понятным конфигурационным файлом в формате `KDL`.

---

## 💡 Что он делает? (Простым языком)

Представь, что у твоего рабочего окружения появился единый «мозг». Демон запускается в фоне и:
1. **Слушает клавиатуру**: Перехватывает глобальные горячие клавиши (включая мультимедийные клавиши громкости и плеера).
2. **Следит за окнами**: Понимает, когда ты переключил рабочий стол, создал новое окно или сменил фокус.
3. **Автоматизирует запуск сервисов**: Сам запускает и контролирует фоновые утилиты (композитор `picom`, уведомления `dunst` и т.д.).
4. **Управляет VPN**: Поднимает и опускает туннели по нажатию клавиш или по триггерам.
5. **Раскидывает окна по мониторам**: Позволяет одной кнопкой отправить браузер на левый монитор, а Telegram — на правый, автоматически создавая нужные воркспейсы.

---

## 🛠 Ключевые фичи

- **Всё в одном конфиге (`config.kdl`)**: Никакого bash-спагетти. Хоткеи, автозапуск, воркспейсы и VPN настраиваются в одном структурированном файле.
- **Умные воркспейсы (Workspaces)**: Перемещение окон приложений (по их классу) на нужные рабочие столы конкретных мониторов с автоматической фокусировкой и установкой правил спавна для новых окон.
- **Реактивные триггеры**: Возможность автоматически выполнять действия при наступлении событий (например: «когда фокус переходит на рабочий стол X — запустить скрипт Y»).
- **IPC-управление**: Демон создает локальный UNIX-сокет. Ты можешь управлять им из терминала или внешних скриптов с помощью CLI-утилиты `de-action`.
- **Написан на Rust**: Потребляет крошечное количество оперативной памяти и процессора, не течет (благодаря аллокатору `mimalloc`) и работает мгновенно.

## 🚀 Быстрый старт

### 1. Требования
- Линукс с X11 сессией (для глобальных хоткеев).
- Установленный оконный менеджер (сейчас полностью поддерживается `bspwm`, есть архитектурный задел под `hyprland`).
- Утилиты `playerctl` (для медиа-клавиш), `xprop` (для определения окон).

### 2. Сборка
Собери проект с помощью Cargo:
```bash
cargo build --release
```
Бинарник демона будет лежать в `target/release/de-configurator`.

### 3. Пример конфигурации
Создай файл конфигурации. Демон ищет его по пути `~/.config/de-configurator/config.kdl` (или в текущей директории при разработке).

Пример простого `config.kdl`:
```kdl
// Включение и привязка окон к рабочим столам
feature "workspaces" enabled=true {
    workspace "browser" class="Brave-browser"
    workspace "telegram" class="TelegramDesktop"
}

// Управление фоновыми процессами
feature "daemons" enabled=true {
    daemon "picom" exec="picom" autostart=true
    daemon "dunst" exec="dunst" autostart=true
}

// Настройка горячих клавиш
feature "keybinds" enabled=true {
    // Запуск терминала
    bind "alt+c" {
        run "alacritty"
    }

    // Переброс Telegram на HDMI-0 монитор
    bind "alt+a" {
        workspace "telegram" "HDMI-0"
    }

    // Управление музыкой (медиа-клавиши автоматически нормализуются)
    bind "mediaplaypause" {
        run "playerctl" "play-pause"
    }
}
```

### 4. Запуск
Просто запусти демон в фоновом режиме (например, прописав в автозапуск X-сессии):
```bash
de-configurator &
```

## 🎮 Управление через CLI (`de-action`)

С демоном можно общаться через UNIX-сокет `/tmp/de-configurator.sock`. Для этого используется утилита `de-action`.

Примеры команд:
```bash
# Переключить VPN на профиль "warp"
de-action vpn warp

# Запустить или перезапустить picom
de-action daemon picom toggle

# Активировать воркспейс браузера на мониторе VGA-0
de-action workspace browser VGA-0
```
С помощью `de-action` можно легко вешать сложные действия на события в других системных утилитах.

## ⚙️ Полное руководство по конфигурации (config.kdl)

Конфигурационный файл использует удобный человекочитаемый формат [KDL](https://kdl.land/). Ниже описаны все поддерживаемые фичи и синтаксис их настройки.

### 1. VPN-соединения (`feature "vpn"`)
Позволяет описывать различные профили VPN.
* `state "имя_состояния"` — уникальный идентификатор профиля (например, `"warp"`, `"finland"`, `"off"`).
* `display-name` — понятное имя для уведомлений.
* `interface` — имя сетевого интерфейса VPN.
* `up-cmd` / `down-cmd` — команда запуска/остановки VPN (список аргументов).

Пример:
```kdl
feature "vpn" enabled=true {
    state "off" {
        display-name "VPN выключен"
    }
    state "warp" {
        display-name "Cloudflare Warp"
        interface "wg-warp"
        up-cmd "wg-quick" "up" "warp"
        down-cmd "wg-quick" "down" "warp"
    }
}
```

### 2. Фоновые демоны (`feature "daemons"`)
Контролирует автозапуск и перезапуск системных утилит.
* `daemon "имя"` — название демона.
* `autostart=true` — запускать ли автоматически при старте.
* `display-name` — имя для уведомлений.
* `start-cmd` — команда запуска со всеми аргументами.

Пример:
```kdl
feature "daemons" enabled=true {
    daemon "picom" autostart=true {
        display-name "Picom Compositor"
        start-cmd "picom" "-b"
    }
}
```

### 3. Экшены (`feature "actions"`)
Позволяет группировать последовательности команд в именованные макросы (экшены).
* `action "имя" export=true` — экшен с флагом `export=true` можно напрямую вызывать из CLI-утилиты `de-action`.
* Внутри экшена можно использовать команды:
  * `vpn "имя_состояния"` — переключение VPN.
  * `daemon "имя_демона" "on|off|toggle"` — управление демонами.
  * `workspace "имя_воркспейса" ["имя_монитора"]` — переключение рабочих пространств.

Пример:
```kdl
feature "actions" enabled=true {
    action "game-mode" export=true {
        vpn "warp"
        daemon "picom" "off" // отключаем композитор для повышения FPS
    }
}
```

### 4. Реактивные триггеры (`feature "triggers"`)
Позволяет вешать автоматическое выполнение команд на события.
* `trigger "имя" type="wm"` — триггер на событие оконного менеджера:
  * `event "desktop_focus"` — переключение рабочего стола.
  * `event "node_focus"` — фокус на окно.
* `trigger "имя" type="interval"` — триггер по таймеру (интервальный):
  * `interval "1m"` (1 минута, поддерживаются секунды `s`, часы `h`).
* `run "команда" "аргумент1" ...` — команда для выполнения.

Пример:
```kdl
feature "triggers" enabled=true {
    trigger "periodic-check" type="interval" {
        interval "5m"
        run "notify-send" "DE" "System check run"
    }
}
```

### 5. Аппликейшен воркспейсы (`feature "workspaces"`)
Связывает классы окон приложений (можно узнать через `xprop`) с логическими воркспейсами.
* `workspace "имя_воркспейса" class="ИмяКлассаОкна"` — например, `Brave-browser`, `AyuGramDesktop`, `discord`.

Пример:
```kdl
feature "workspaces" enabled=true {
    workspace "browser" class="Brave-browser"
    workspace "telegram" class="AyuGramDesktop"
}
```

### 6. Горячие клавиши (`feature "keybinds"`)
Биндит клавиши на действия.
* Поддерживает модификаторы: `ctrl`, `shift`, `alt`, `super`.
* Автоматически нормализует и поддерживает медиа-клавиши: `mediaplaypause`, `mediatracknext`, `mediatrackprevious`, `audiovolumeup`, `audiovolumedown`, `audiovolumemute`.
* Действия внутри бинда:
  * `run "команда" "аргументы"...` — выполнить внешнюю команду.
  * `vpn "имя_состояния"` — переключить VPN.
  * `action "имя_экшена"` — выполнить экшен.
  * `workspace "имя_воркспейса" ["имя_монитора"]` — перебросить/активировать воркспейс на мониторе.

Пример:
```kdl
feature "keybinds" enabled=true {
    bind "super+ctrl+g" {
        action "game-mode"
    }
    bind "alt+b" {
        workspace "browser" "HDMI-0" // фокус браузера строго на HDMI-0
    }
}
```
